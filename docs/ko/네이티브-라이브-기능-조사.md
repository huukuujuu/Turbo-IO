# 안경 네이티브 라이브 기능 조사

대상: RayNeo iO-B972 / Strix OS 1.0.6.14, Turbo IO 독립 iOS 앱 0.2.0 빌드 10–14.

## 확인한 사실

| 메뉴 | 시작 채널 | 시작 메시지 | 관찰된 설정 |
| --- | --- | --- | --- |
| Live Captions | business 19 (aiSubtitle) | type1, code1 | mode classic, source_language en-US, target_language zh-CN |
| Live Answers | business 23 (proactiveAi) | type1, code1 | mode classic, src_lang/dst_lang 필드 존재 |

Live Answers에는 별도의 type11 연결 상태 메시지도 있습니다. 상태 값의 의미는 확인하지 않았습니다. 세션 ID, 사용자 발화 및 오디오는 이 문서나 Git에 보관하지 않습니다.

## 제한된 실기기 시험

- 빌드 12: 자막 type2에 sid/code1/settings 응답.
- 빌드 13: 자막 type2에 sid/code0/settings 응답. Live Answers는 구조 관찰만 수행.
- 빌드 14: 두 채널의 type2에 sid/rc1 응답. 이는 일반 음성 대화에서 사용되는 형태를 비교한 것이며 두 기능의 확인된 규격이 아닙니다.
- 각 시험은 최대 8초, 오디오 패킷 수와 길이만 집계합니다. 디코딩·파일 저장·클라우드 전송은 없습니다.
- 결과: Live Captions는 바로 닫히고 Live Answers는 unknown error. 대상 채널 오디오 수신 0패킷. 기능 복원 미완료.

## 후속 확인 지점

공식 다운로드 페이지가 제공하는 Android 1.0.25의 라이브러리 문자열에서 `CaptionStartResultModel`, `CaptionStartResultCode`, `sendStartResultAndConfigSync`, `ProactiveAiGlassesService`, `ProactiveAiCaptionConflictCoordinator`를 확인했습니다. 이는 시작 결과·설정 동기화와 별도 서비스가 존재한다는 단서이며, JSON 필드나 성공 코드 또는 호출 순서를 입증하지 않습니다. 공식 바이너리는 저장소에 포함하지 않습니다.

다음 단계는 공식 앱에서 시작 결과와 설정 동기화의 실제 구조·순서·오디오 라우팅을 확인하는 것입니다. 단순히 code/rc 값을 더 바꿔 보는 시험은 중단했습니다. 오디오 전달이 확인된 뒤에 ASR 연결, 자막 표시, 주변 대화에 대한 답변 제안 구현을 진행해야 합니다.

## 일반 사용 복귀

빌드 14 시험 후 개발 실행 인자를 제거하고 앱을 다시 실행했습니다. `--probe-caption-handshake` 없는 일반 실행은 시작 응답 실험을 활성화하지 않습니다. 일반 음성 AI 사용 시 대화 화면에서 음성 대기를 켜면 됩니다.
