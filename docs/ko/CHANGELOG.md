# 한국어 iPhone 빌드 변경 이력

기준 원본: Turbo1123/Turbo-IO, 커밋 `28a0fef0a42773f38222fcd0db2e0f2852ed4257`.
경로: V1 독립 SDK iPhone 앱. 공식 앱 확장(V2) 및 펌웨어 변경은 포함하지 않습니다.

## 2026-11-18 · 0.2.0 (10) · 메뉴 연동 조사

- Live Captions / Live Answers의 안경 메뉴 연동을 조사하기 위한 읽기 전용 진단입니다. 기능 복원 완료 버전이 아닙니다.
- AI 자막 채널(business 19)의 메시지 종류·길이와 JSON 필드명, 제한된 제어 값만 표시합니다. AI 메뉴의 비오디오 제어 메시지에도 같은 구조 요약을 추가했습니다.
- 음성·인식문·토큰·세션 ID 등 원문 값은 출력하지 않습니다. 이 변경만으로 녹음이나 클라우드 인식을 시작하지 않습니다.
- 기존 V2의 자막 표시는 공식 앱의 세션 연결에 의존합니다. V1로 옮기기 전 현재 기기의 메뉴 시작·종료 및 오디오 요청 프로토콜을 확인해야 합니다.

## 2026-11-18 · 0.2.0 (9)

- 빌드 8에서 긴 답변 전송 10초 후 마이크를 끄고 읽기 화면을 유지하여 끼어들기가 막히는 회귀를 수정합니다. 기기 로그에서는 약 370자 답변 전송 26초 뒤에 type11 다음 대화 요청이 수신됐으나 읽기 상태에서 무시되고 있었습니다.
- 연속 모드의 답변 표시 중 ASR을 유지합니다. 전송 완료 후 첫 type11 다음 대화 요청이 오면 후속 질문 대기를 10초로 줄입니다. type11을 렌즈 렌더 완료 ACK로 해석하지 않습니다.
- 중복 type11은 대기 시간을 연장하지 않습니다. 유효한 새 발화는 기존 종료 타이머를 취소합니다. 신호가 없을 때만 길이 기반 30~120초 예비 종료를 사용하며 120초 음성 세션 보호는 유지합니다.
- 오디오 손실·세션 상한으로 이미 마이크가 중지된 읽기 상태에서도 다음 대화 요청이 오면 새 음성 세션을 시작할 수 있게 합니다. 표시 중 ASR 사용량이 발생할 수 있음을 앱에 표시합니다.
- 회귀 검사: 40/64/100/360/370/382/800자 답변에서 10초 후 끼어들기, type11 후 10초 종료, 중복 이벤트, 예비 종료, 수동 종료, 오디오 복구, 세션 상한을 검사합니다. 실제 안경의 렌더 동작과 대화 전환은 추가 실기기 검증이 필요합니다.

## 2026-11-18 · 0.2.0 (8)

- 답변 전송 완료 10초 후 자동 종료 명령이 긴 답변 표시를 끊는 로그를 확인했습니다. 전송 완료는 렌즈의 렌더링·읽기 완료를 뜻하지 않습니다.
- 후속 질문 듣기(10초)와 화면 읽기 시간을 분리했습니다. 후속 질문이 없으면 마이크·ASR을 종료하고, 전송 완료 시점부터 답변 길이 기준 초당 5자 추정으로 최소 30초~최대 180초 화면 유지 시간을 부여합니다.
- 읽기 중 새 음성 호출과 안경의 수동 종료를 처리합니다. 마이크의 120초 제한이나 오디오 콜백 중단이 이미 완성된 답변의 읽기 화면을 즉시 종료하지 않도록 분리합니다. 진행 중인 음성 처리 보호 제한은 유지합니다.
- 시계 기반 회귀 검사 `core-probe/Tests/AnswerReadingTests.swift`: 긴/짧은 답변 유지, 마이크 종료 후 화면 유지, 새 호출, 수동 종료, 120초 경계 확인 통과. 실제 안경이 자체적으로 화면을 종료하는 경우나 읽기 완료 확인은 별도 실기기 검증이 필요합니다.

## 2026-11-18 · 0.2.0 (7)

- Codex 미확인 요청이 있을 때 새 전송·작업 전환이 잠기는 이유와 마지막 오류를 표시합니다. 재확인 실패의 오류도 화면과 앱 재실행 후에 유지합니다.
- PC 처리 여부를 사용자가 직접 확인한 뒤 아이폰의 전송 보류만 명시적으로 해제하는 기능을 추가했습니다. PC 작업 중지, 자동 재전송, 승인 처리 또는 서버 원장의 변경은 하지 않습니다.
- 기존 답변이 새 요청의 응답처럼 보이지 않도록 미확인 상태의 안내를 보강했습니다. 실제 모델의 동일 응답 생성 원인은 이 UI 변경만으로 확정하거나 해결했다고 볼 수 없습니다.
- `codex-bridge/diagnose.mjs`는 Linux에서 고정된 서로 다른 문장 3개(같은 작업 2회, 새 작업 1회)를 보내 비교합니다. 토큰과 실제 답변은 출력하지 않고, 접수 ID와 예상 문구 일치 여부·답변 해시만 출력합니다.
- 검증: Codex 단위 테스트 10개 통과(보류 해제가 네트워크 호출·작업 선택을 변경하지 않고 앱 재실행 후에도 해제되는지 포함), 기기 빌드·서명 검사 및 한국어 정적 검사 통과. 원격 Linux에서의 동일 응답 현상은 아직 재현하지 못했습니다.

### 검증

- 전체 한국어 검수 시 단위 테스트 217개 및 UI 순회 테스트 1개 통과, 화면 6개 육안 확인.
- 최종 진단 변경 후 iPhone 기기용 빌드, 서명 및 설치 확인. 실제 기기에서 HTTP 402 처리와 API 잔액 조회를 확인했습니다.
- 한국어 정적 검사: 미번역 UI 0줄, 유지한 내부 선택·저장값 14줄.
- `git diff --check` 통과. Codex 브리지 테스트 15개 통과, 로컬 인증된 상태 조회 및 미인증 401 차단 확인.

### 기능 범위

- 실제 음성 대화는 Alibaba ASR → DeepSeek → 텍스트 표시 조합입니다. 다른 모델 설정 초안은 이 실행 경로를 바꾸지 않습니다.
- 공식 안경 메뉴의 라이브 캡션·실시간 번역과 답변 TTS는 이 V1 빌드에 연결되지 않았습니다.
- 정상 유료 모델 응답, 자막, 모든 안경 화면의 동작을 검증했다는 의미는 아닙니다.
- Codex는 별도 PC 브리지가 필요합니다. 원격 Linux 배포는 안내만 제공했으며 원격 기기에서 검증하지 않았습니다.

### 재현 및 이력 관리

`python3 localizations/audit_ko.py`로 한국어 UI를 검사합니다. 기기 빌드는
`apps/RayNeoCompanion/project-device.yml`을 XcodeGen으로 생성한 뒤
`RayNeoCompanionDevice` 스킴과 본인의 Apple 개발 팀으로 빌드합니다.
실기기 테스트에는 본인의 안경과 서비스 자격 증명이 필요합니다.

변경은 `ko/ios-personal` 브랜치에서 커밋하고 개인 fork의 `origin`에 푸시합니다.
원본 업데이트는 `git fetch upstream`으로 가져온 뒤 검토하여 병합합니다.
로그·빌드 결과·SwiftPM 사용자 설정·API 키·서명 인증서는 커밋하지 않습니다.
